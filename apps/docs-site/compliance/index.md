# 合规框架

SeekAll 的合规设计基于 4 个支柱：

## 1. 工具中性

SeekAll 是一个 npm 包（SDK），做什么由用户写的规则决定。
服务端不替用户跑规则，不存搜索结果，不向资源站发 outbound 请求。

类比：ffmpeg 是视频处理工具，没人因为有人拿它转码盗版电影就告 ffmpeg。

## 2. 默认 0 规则

SeekAll 默认不内置任何指向具体网盘 / 磁力站 / 盗版论坛的规则。
用户想搜什么，自己写规则或从市场挑选。

## 3. 风险分级 + 严格权限

5 级风险评级（L0-L4），L3/L4 规则仅 admin 可见，仅作审计。
5 维权限矩阵严格映射会员档。

详见 [5 级风险评级](/guide/risk-levels) 和 [5 维权限矩阵](/guide/permission-matrix)。

## 4. DMCA 流程

- DMCA 邮箱：`1660069758@qq.com`
- 24h 内人工响应
- Takedown 记录在 AuditLog 表
- 触发 Provider 过滤

详见 [DMCA 流程](dmca) 和 [Takedown 政策](takedown)。

## 不做的事

- ❌ 不教用户接盗版源（文档零提及具体网盘/磁力站）
- ❌ 不托管规则代码（代码在 npm 上）
- ❌ 不向 L3/L4 规则的资源站发服务器侧请求
- ❌ 不存搜索结果
- ❌ 不做评论 / 评分 / 论坛（避免社区化带来的侵权风险）

## 协议

- SDK 核心：AGPL-3.0（强 copyleft，衍生作品必须开源）
- 插件：MIT（宽松，鼓励社区贡献）
- 服务端 BaaS：BUSL（商业源码许可，保护服务端代码）
